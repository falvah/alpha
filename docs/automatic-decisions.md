# Автоматические решения по полной карте

Основной проект: `/home/xal/ALFA_HACKATON`. Обычная заявка использует тот же полный движок из `docs/reference/mlcard`, что и JSON-скоринг. Условный расчёт по свободному денежному потоку удалён. Подробности формул и серой зоны — в [scorecard.md](scorecard.md).

## Источник данных

Миграция `0006` добавляет `Company.trusted_scoring_data`: проверенные обогащение и показатели документа, дату оценки, признак демонстрационных данных, ревизию и снимок профиля. Клиентские формы не могут записывать это поле. Сумма, срок, цель и реквизиты для расчёта всегда берутся из отправляемой заявки; параметры исходного JSON не подменяют запрос клиента.

Серверный импорт готового JSON с ИНН и ОГРН компании:

```sh
.venv/bin/python manage.py import_scoring_data 7701234567 /path/to/checked-input.json
# Для явно демонстрационного источника:
.venv/bin/python manage.py import_scoring_data 7701234567 /path/to/example.json --simulated
```

Формат входа — исходные примеры `fixtures/scorecard/*.json`. Импорт не принимает решения по ранее отправленным заявкам: он готовит источник для следующей отправки. Команда проверяет размер JSON, структуру, значения и принадлежность компании. Внешний провайдер может вызывать тот же серверный `store_source`.

`seed_workspace` создаёт явные синтетические источники для демонстрационных профилей и добавляет их существующим профилям, если источник ещё не задан. Эти данные доступны только в SANDBOX_MODE. Полноценный проверенный источник без признака `simulated` поддерживается и вне тестового режима. Реальных интеграций с БКИ/реестрами и распознавания PDF пока нет.

Изменение сведений компании, данные старше 30 дней или дата из будущего требуют обновления источника. После запроса уточнений прежнюю ревизию нельзя автоматически использовать повторно. Недостаточные/противоречивые данные передаются эксперту без выдумывания благополучных проверок. Срок актуальности задаёт `SCORECARD_DATA_MAX_AGE_DAYS`.

## Результат отправки

1. Согласие, анкета и документы проверяются сервером.
2. Полная карта рассчитывает факторы, покрытие, PD, стопы, лимит, ставку и платёж.
3. Клиент сразу получает одобрение, отказ, уменьшенную сумму с отдельным принятием условий либо сообщение о направлении эксперту.
4. Исходные данные, результат, ревизия источника, дата и история сохраняются в одной транзакции.

Эксперт может дополнить данные через «Скоринговая карта → Рассчитать решение» в карточке заявки. Для серой зоны он принимает решение в рамках рассчитанных моделью условий. Для пропусков данных сначала требуется свежий JSON-расчёт.

`/bank/` — очередь спорных случаев и уточнений. `/bank/?view=history` — все отправленные заявки, автоматические и ручные решения. `/bank/audit/` — история операций. Черновики остаются закрытыми для эксперта. Готовое автоматическое решение нельзя взять в работу повторно, назначенную заявку нельзя забрать у другого эксперта.

Старые заявки и их история не переписываются задним числом. Контрольные сценарии после смены модели создаются отдельно; повторная загрузка при неизменных входах и модели не дублирует их.

## Обновление

```sh
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python manage.py migrate --noinput
.venv/bin/python manage.py seed_workspace
sh scripts/check.sh
```
