# Сценарии и UX

Проект основан на анализе предоставленного кейса, а не на проведённых интервью. Ниже — продуктовые гипотезы для последующей проверки с предпринимателями и сотрудниками.

| Участник и задача | Препятствие | Решение интерфейса |
|---|---|---|
| Предприниматель: выбрать финансирование | Банковские термины и непонятный платёж | Три карточки с конкретными целями, лимитами и калькулятором |
| Предприниматель: заполнить заявку | Повторный ввод и длинная анкета | Три шага, заполненный профиль, сохранение при переходе дальше |
| Предприниматель: понять, что делать | Непрозрачный статус | Ясные подписи, баннер следующего действия и история |
| Предприниматель: исправить сведения | Непонятный запрос банка | Комментарий в контексте той же заявки, повторная отправка |
| Предприниматель: оценить новые условия | Неясное отличие от запроса | Исходные и предложенные параметры рядом, платёж и график |
| Эксперт: обрабатывать очередь | Потеря контекста между системами | Поиск по компании/ИНН, фильтры, назначение ответственного |
| Эксперт: обосновать решение | Непрозрачный итоговый балл | Факторы оценки с баллами, документы и снимок финансов рядом |

Главная организована вокруг задач: подобрать кредит, продолжить заявку, ответить банку. Вторичные документы и уведомления вынесены в навигацию. Красный используется для основного действия, зелёный — для результата, тёплый жёлтый — для уточнений. Статус передаётся текстом, а не только цветом.

Формы проверяются на сервере. Ошибки рядом с полем; данные не сбрасываются при обычной ошибке в анкете. Для опасной отмены есть подтверждение браузера; для выдачи — отдельное согласие с условиями. Калькулятор считает на сервере и переносит валидные выбранные параметры в заявку.

Вся графика локальная и сделана в CSS/SVG, системные шрифты не требуют интернета. Интерфейс адаптируется к узким экранам; таблицы допускают горизонтальную прокрутку. Кнопки доступны с клавиатуры, фокус выделен, есть переход к содержимому, reduced-motion и подписи иконок. Формального аудита WCAG не проводилось.

## Объяснимость правил

Используется полная [скоринговая карта из «млка»](scorecard.md): факторы → PD → стопы → лимит и ставка. Результат включает причины и вклад факторов. Однозначные заявки обрабатываются автоматически, серая зона и неполные данные передаются эксперту.

## Что проверять с пользователями

- Может ли предприниматель без подсказки выбрать продукт и найти платёж?
- Понятно ли, когда черновик сохранён, а когда данные ещё не сохранены?
- Может ли клиент найти комментарий банка и успешно повторно подать заявку?
- Отличает ли клиент исходный запрос от встречного предложения?
- Может ли сотрудник объяснить решение по данным из одной карточки?

Целевые метрики для будущей проверки: завершение сценария, число возвратов на предыдущий шаг, время ответа на уточнение, число ошибок форм, время сотрудника на решение. Измеренные результаты не заявляются.
